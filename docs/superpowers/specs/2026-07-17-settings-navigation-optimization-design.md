# 设置页返回与关键易用性优化设计

**日期：** 2026-07-17  
**范围：** AMAX Dashboard 静态前端（`dist/index.html`、`dist/style.css`、`dist/app.js`）

## 目标

1. 用户从看板进入设置页后可以安全返回看板。
2. 设置页存在未保存输入时，返回前必须确认是否放弃修改。
3. 修复设置读取失败被静默忽略、表单只能点击提交、页面切换语义不完整等关键易用性问题。
4. 保持现有视觉风格、Rust IPC、数据库、托盘和定时刷新行为不变。

## 非目标

- 不重构整体视觉设计。
- 不引入前端框架或构建步骤。
- 不修改 IPC command、Rust 后端或持久化格式。
- 不返回尚未成功加载过数据的空看板。

## 方案

在现有 `dist/app.js` 内集中管理页面与配置表单状态，不引入完整状态机。

新增或明确以下状态和职责：

- `canReturnToDashboard`：当前会话是否存在已成功渲染的看板。
- `configBaseline`：进入设置页时的 Cookie 与 API Key 输入基准。
- `isConfigDirty()`：比较当前输入和基准，判断是否有未保存修改。
- `openSettings()`：读取配置、初始化表单并进入设置页。
- `leaveSettings()`：执行脏数据确认、清理设置状态并返回看板。
- 保存中状态：统一控制保存按钮、返回按钮及 `aria-busy`。

相比直接增加按钮和 `confirm()`，集中入口能避免按钮状态、表单基准和错误反馈散落在多个事件处理器中。完整状态机对当前两页应用属于过度设计。

## 页面导航

### 返回按钮

- 配置页标题区增加可见文本“返回看板”的按钮。
- 只有 `canReturnToDashboard` 为真时显示。
- 首次启动、Cookie 过期或认证失败进入配置页时隐藏。
- 保存过程中禁用，防止请求状态和页面状态分离。

### 返回规则

1. 表单未修改：直接返回看板。
2. 表单已修改：调用原生确认框，提示“放弃未保存的修改并返回吗？”。
3. 用户取消：保留页面、输入和焦点。
4. 用户确认：清空输入和设置状态，返回现有看板，不触发刷新。
5. `Escape` 执行相同流程；保存过程中忽略该操作。

已保存凭据不会回填到输入框，因此从看板进入设置页时空输入是基准。输入任意 Cookie 或 API Key 都视为修改。

## 设置与保存流程

### 打开设置

1. 用户点击看板的设置按钮。
2. 调用 `get_config`。
3. 成功后清空敏感输入，按 `has_cookie` 和 `has_api_key` 设置占位文字，清除旧状态，记录空表单基准并进入配置页。
4. 进入后聚焦 Cookie 输入框。
5. 若读取失败，停留看板并显示“无法打开设置”及可用的具体错误，不进入状态不完整的配置页。

### 保存配置

- 配置表单改为标准 `submit` 流程，点击按钮或按 `Enter` 均可提交。
- 沿用 Cookie 自动补全 `session=` 和最小长度校验。
- 提交时禁用保存与返回按钮，并为表单设置 `aria-busy="true"`。
- 保存成功后调用现有 `loadDashboard()`，验证并进入看板。
- 保存失败时恢复按钮和 `aria-busy`，保留输入并显示具体错误。
- 所有异常使用统一辅助函数提取字符串，避免 `[object Object]`。

## 看板刷新与后台事件

- 保留 `dashboardRequest` 的并发请求合并逻辑。
- 手动刷新失败时保留已有数据和原更新时间。
- 只有成功执行 `renderDashboard()` 后，才允许从设置页返回看板。
- 认证失败时清除返回资格，强制进入设置页并提示重新获取 Cookie。
- 后台 `dashboard-updated` 事件可更新已初始化看板，但不能让首次配置页或认证失败页获得返回空看板的资格。

## 可访问性与焦点

- 页面切换同时维护 `.hidden` 和 `aria-hidden`。
- 返回按钮具有可见文本和明确的 `aria-label`。
- 表单保存状态通过 `aria-busy` 表达。
- 进入设置页后聚焦 Cookie 输入框。
- 返回看板后聚焦设置按钮。
- 原有状态区域继续使用 `role="status"` / `aria-live="polite"`，看板错误继续使用 `role="alert"`。

## 错误处理

| 场景 | 行为 |
| --- | --- |
| `get_config` 失败 | 停留看板，显示“无法打开设置” |
| 用户取消放弃修改 | 保持设置页、输入和焦点 |
| 保存失败 | 恢复按钮，保留输入，显示具体错误 |
| 认证失败 | 清除返回资格，进入设置页并隐藏返回按钮 |
| 网络刷新失败 | 保留已有看板数据和更新时间 |
| 未知异常对象 | 统一转换为可读字符串 |

## 文件变更

- `dist/index.html`：配置页返回按钮、标准表单提交语义、必要的 ARIA 属性。
- `dist/style.css`：返回按钮沿用现有按钮体系所需的少量样式，不改变视觉语言。
- `dist/app.js`：集中设置页进入/离开、脏数据判断、保存忙碌状态、错误提取、焦点和 ARIA 同步。

## 验证

### 静态和自动化检查

```bash
node --check dist/app.js
cargo fmt --all -- --check
cargo check --workspace
cargo test --workspace
```

### 真实应用验证

运行 `cargo tauri dev`，验证：

1. 看板进入设置页后，无修改可直接返回。
2. 修改凭据后返回，确认框的取消和确认分支均正确。
3. `Escape` 使用相同返回规则。
4. `Enter` 能提交表单。
5. 保存和刷新期间按钮状态正确。
6. 首次启动、Cookie 过期和认证失败时不能返回空看板。
7. 设置读取失败时停留看板并显示错误。
8. 窗口、托盘和后台刷新无回归。

若已有 `amax.exe` 运行，停止真实应用验证并请用户关闭，不主动终止未知进程。
