# AMAX Dashboard A2 平衡科技页面优化设计

## 目标

在不改变 AMAX Dashboard 数据接口和核心流程的前提下，重构配置页与看板页的视觉表达，移除模板化卡片、霓虹多强调色、功能性 emoji 和常见 AI 生成感，形成克制、清晰、具有轻度科技气质的桌面工具界面。

## 现状审计

当前页面存在以下问题：

- 紫黑背景叠加青、橙、绿、红多种高饱和强调色，接近常见 AI Dashboard 配色。
- 今日费用、Token 和额度均采用“背景 + 边框 + 统一圆角”的等权卡片，信息优先级不清晰。
- emoji 同时承担标题装饰、状态和按钮图标，风格不统一。
- 配置页是居中通用登录卡片，缺少产品辨识度。
- 标题、标签、数字均使用同一系统字体，数据排版缺少精密感。
- API Key 文案暗示其参与今日消耗查询，与当前后端实际行为不一致。
- Cookie 过期提示仍写“超过 24 小时”，与固定 15 天有效期不一致。
- 输入框缺少明确的 `focus-visible` 状态，交互状态不完整。

## 视觉方向

采用已确认的 **A2 平衡科技**：编辑式信息层级结合成熟开发工具的精密感。

### 色彩

- 页面基底使用浅色冷灰绿，不使用纯白或紫黑。
- 正文使用近黑冷绿色。
- 森林绿是唯一常规强调色，用于同步状态、关键数据、焦点和进度。
- 次级文字与分隔线使用同一冷灰绿体系。
- 错误状态可使用低饱和红色，但不得成为常规视觉强调色。
- 不使用渐变、玻璃拟态、霓虹发光或多彩阴影。

### 字体与数字

- 中文正文和标题使用 Windows 系统无衬线字体栈，不加载外部字体。
- 金额、Token、百分比和遥测标签使用等宽字体栈或 `font-variant-numeric: tabular-nums`。
- 主金额使用紧凑字距和大字号，成为第一视觉焦点。
- 标签可使用短英文遥测词，如 `COST TODAY`、`TOKENS`、`AVAILABLE QUOTA`；说明和操作文案保持中文。

### 表面与装饰

- 内容区加入极淡的 24px 精密网格，透明度必须足够低，不影响文字读取。
- 主要数据采用开放式布局和细分隔线，不使用通用卡片阵列。
- 额度区使用左侧森林绿强调轨道和细进度条。
- 输入框与按钮使用小圆角；主要数据区接近直角。
- 去除全部功能性 emoji；刷新和设置使用内联 SVG 线性图标，笔画风格一致。

## 看板页结构

### 顶栏

- 左侧显示 `AMAX / DAILY`。
- 右侧显示同步状态、刷新按钮和设置按钮。
- 同步状态以小型状态点加相对更新时间呈现。
- 顶栏保持紧凑，不使用独立深色块制造割裂。

### 用户与主指标

- 用户标题改为“`<display_name>` 的今日用量”。
- 累计请求数和更新时间合并为次级元信息。
- 今日费用独占主要展示区域，保留现有 6 位小数精度和人民币符号。
- 不使用问候 emoji 或口语化欢迎语。

### Token 区

- Token 总量与输入/输出采用开放式双列分区。
- 两列通过细分隔线组织，不添加卡片背景和阴影。
- 数据不可用时分别显示“暂不可用”和“日志接口暂不可用”，不影响额度区。

### 额度区

- 展示剩余百分比、剩余金额、已使用金额和总额。
- 百分比为第二层级大数字。
- 进度条保持真实剩余比例，宽度限制在 0–100%。
- 左侧强调轨道用于区分额度区，不再使用完整边框卡片。

## 配置页结构

- 使用与看板一致的浅色冷灰绿、网格、字体和分隔线系统。
- 页面左对齐，不使用居中通用登录卡片。
- 顶部显示 `AMAX / ACCESS` 和简短认证说明。
- Cookie 获取步骤改为清晰的编号操作清单。
- Cookie 输入仍为密码类型，保留自动补全 `session=` 和长度校验。
- API Key 标注为可选，说明改为“兼容配置，当前账户汇总无需填写”。
- 主按钮文案改为“保存并验证”，移除保存 emoji。
- 状态与错误保持表单内联展示，不使用弹窗。
- 已保存凭据的留空不修改行为保持不变。

## 状态与交互

### 加载

- 骨架屏必须匹配新布局：用户元信息、主金额、双列 Token 和额度轨道。
- 不再模拟三张通用卡片。
- 刷新按钮加载时旋转，继续禁用按钮并复用现有并发请求合并逻辑。

### 错误

- 网络或普通刷新失败时保留已有数据，在顶栏下方显示紧凑错误条。
- 首次加载失败时显示独立错误状态，但不伪造数据。
- 认证失败时返回配置页并提示重新获取 Cookie。
- Cookie 本地过期提示改为“Cookie 已过期（超过 15 天），请重新获取”。
- 日志聚合不可用时保留额度数据，并仅降级费用与 Token 区。

### 可访问性与动效

- 所有按钮和输入框提供清晰的 `focus-visible` 样式。
- 图标按钮保留可读的 `aria-label` 和 `title`。
- hover 使用颜色或背景变化；pressed 使用轻微位移或缩放。
- 动画只改变 `transform` 和 `opacity`，进度条宽度更新除外。
- 使用 `prefers-reduced-motion` 关闭非必要动画。
- 正文允许文本选择；只对纯装饰或按钮区域限制选择。

## 技术范围

修改范围限定为：

- `dist/index.html`：重构语义结构、文案和内联 SVG 图标。
- `dist/style.css`：替换视觉变量、布局、状态和响应式样式。
- `dist/app.js`：适配文案与必要的 DOM 输出，不改变 IPC command、事件名称或请求流程。

不修改：

- Rust 后端和数据库。
- `get_config`、`save_config`、`fetch_dashboard` command。
- `dashboard-updated` 事件。
- Tauri 窗口尺寸 `520×680`。
- 数据字段、金额精度和 Token 格式化规则。
- 外部依赖、字体、图片或构建步骤。

## 响应式约束

- 以现有 `520×680` 桌面窗口为主设计尺寸。
- 内容区允许垂直滚动，配置说明在小高度窗口中不得被裁切。
- 当可用宽度不足时，Token 双列可转为单列，但不得产生横向滚动。
- 按钮点击目标不小于 36×36px。

## 验证

### 静态检查

```bash
node --check dist/app.js
cargo fmt --all -- --check
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

### 真实应用验证

依据项目要求启动真实 Tauri 应用，验证：

1. 无有效凭据时显示新版配置页，窗口内可滚动并可正常输入。
2. Cookie 校验错误以内联状态显示。
3. 保存配置后进入看板。
4. 看板数据、精度、Token 明细、额度比例和更新时间正确。
5. 刷新、设置、后台更新事件和旧数据保留逻辑正常。
6. 加载、日志降级、网络错误和认证失效状态符合设计。
7. 键盘 Tab 顺序、焦点环和 reduced motion 行为正确。
8. 520×680 窗口中无横向滚动、遮挡或内容溢出。

若没有有效凭据，至少验证配置页、窗口生命周期和可离线触发的状态；不得用 `cargo check` 代替真实应用验证。
